# Market finder and browse interaction

The public `/market` page uses EVE Market Browser as a spatial reference: a compact browse rail beside a selected-item detail area. The standalone Market module contributes its sidebar link with a chart-style shell icon and its route; the route is enabled by default but can be disabled through module settings. Later order and history panels extend the detail area. Static SDE data never implies a current price or collected market.

## Browse tree

Pinia Colada SSR-loads the current revision and complete ~25 KB gzip group tree through the generated Hono client. Its transferred query cache prevents a duplicate tree request on hydration. Reka Tree supplies group and item semantics, keyboard navigation, selection, and controlled expansion through `UiTreeRoot` and `UiTreeItem` in the shared UI layer. The hierarchy and names come from the SDE-backed API, never a hardcoded category list. Siblings at each level are sorted by English display name before the visible 100-subgroup window; direct-type cursors remain in their API order.

On desktop the rail is a separate bordered panel 13.75–17 rem wide beside the detail panel. It stays in view while the page scrolls and scrolls its own tree. Browse and Quickbar are two equal-width tabs with small uppercase labels; the Quickbar tab shows the pinned count. Rows are 32 px with 20 px framed category icons and a chevron that rotates when a group is open; the selected item has a highlight and a left accent bar. The search field is 32 px high with a separate collapse-all button beside it. Below 48 rem the rail stacks above the detail at a bounded height. Tree and Quickbar scrollbars use the standardized thin style; long item names remain on one line with an ellipsis and retain their full accessible name and hover title. Group expansion requests only directly assigned items, 100 per revision/group/cursor-keyed page. The next page appends when an intersection observer sees the end of the current item list. Collapsing stops observation; re-expansion can reuse cached pages. No type page or descendant type request is made by merely browsing a parent. The selected type ID remains in the route query across browse and search. Loading and error states remain visible, but completed pages show no item-range label or Load More control.

Category `iconId` values resolve to bundled images using Vite's asset glob, with a folder fallback. The reference site's local numbered assets cover 386 IDs, and 15 more were resolved through the official build 3542233 `icons.jsonl` icon-file mapping and the local CCP `Icons/items` pack. A fallback covers the remaining 43 of 444 distinct IDs. The reference repo's `apps/website/downloads-icons.sh` fetched CCP's `https://web.ccpgamescdn.com/aws/developers/Uprising_V21.03_Icons.zip` and extracted `Icons/items/*`. SDE icon IDs are not the type IDs supported by `useEveImages()` or the separate `Types/<typeId>_32.png` images.

Bundled category images have a maximum edge of 64 pixels. Oversized originals were downsampled with their transparency and aspect ratio preserved; `21074.png` is 62 × 64 rather than stretched square. ## Finder

The compact input accepts text immediately. The category tree stays visible for fewer than four non-space characters. At four characters, the browser loads the separate revision-keyed global search index, replaces the tree with at most 20 ranked results in the same rail, and announces loading, empty state, or result count. Clearing below four characters restores the tree. Ctrl/Cmd+K focuses the input. No keystroke makes its own HTTP request after the index loads.

Market owns `FuseWorker`, the SDE revision, stable type IDs, and reranking. Exact type ID/name matches precede prefix, substring, multi-token, and bounded fuzzy candidates, with deterministic English-name and numeric-ID ties. Pending replies are scoped to query sequence and revision. A replacement revision clears old group-page bindings and warms a new index before adopting results if search is active. Worker failures report unavailable rather than performing a full-corpus main-thread search.

## Quickbar

The rail reuses `UiTabs` (Reka Tabs) for Browse and Quickbar. Selected items can be pinned or unpinned from the detail header, and catalogue items reveal a pin action on hover or keyboard focus (always visible on touch). Market keeps a validated `__root__` folder tree of public type IDs in browser localStorage under `eve-space-market-quickbar-v1`, migrating the earlier flat ID array on read. It bounds state to 100 distinct types, 50 folders, eight nested levels, and 20 KB of serialized input; malformed or cyclic state cannot authorize or alter catalogue data. Missing IDs in a new SDE revision remain removable instead of being shown as a current item.

Quickbar supports root and nested folders, creation, rename, deletion that promotes children and items to the parent, item/folder moves, clear confirmation, and import/export of EVE Quickbar text through the browser clipboard. Duplicate or ambiguous imported type names are rejected. The current revision's public index resolves pinned IDs and import/export names only when Quickbar is opened; ordinary Browse SSR still transfers just the tree. Quickbar state is independent of account sessions and query persistence.

`MarketQuickbarPanel` renders a header with the item and folder count, a New folder button and an overflow menu (Import from clipboard, Export to clipboard, Clear Quickbar with confirmation). New folders are created as "New folder" and open straight into inline rename: Enter or leaving the field saves, Escape cancels. Rows are 34 px; items show their type icon, folders show a chevron and their item count. Row actions appear on hover or keyboard focus and are always visible on touch: folders offer rename, move and delete (contents move up a level); items offer move and remove. Move opens an inline "Move to" list of folders plus "No folder", marking the current location and disabling folders that would create a cycle. Nesting is created by moving a folder into another.

The shared UI layer owns Reka `UiTreeRoot`/`UiTreeItem`, `UiDraggableTreeItem`, `UiTreeDropZone`, `useUiClipboard`, and the client-only Pragmatic Drag and Drop adapter. Market owns validated folder/item move rules and the serialized format. Nested targets accept only the innermost drop; the inline move list is the keyboard and mobile alternative to dragging.

## Item detail and order book

The detail header shows a 48 px framed type icon (`useEveImages`, with the `bp` variation for blueprints), the category path in small uppercase text, the item name, a bordered Market selector listing only enabled profiles, and a Pin/Unpin action. A summary strip below it reports best sell, best buy, spread with its share of the sell price, and listed units per side. Prices there use compact K/M/B/T display with exact ISK in the title and accessible label. Listed units sum the loaded first page and add "+" when more orders exist.

Sell and buy books sit side by side and stack on narrow widths. Each is a semantic table with sortable Price, Qty, Location and Expires columns and sticky headings. Sellers ascend and buyers descend by exact decimal ISK, with issued time and order ID breaking ties; secondary sorts apply only to the loaded window. Each price shows its difference from the best price on that side ("Best" for the best). In default price order on the first page, a background bar shows cumulative quantity from the best price. Location shows the colored `UiSystemSecurityStatus` value before the exact station label; buy orders add tags for a non-region range and a minimum volume above one. Expiry is compact (for example `89d 23h`, or `23h 18m` under a day) and turns to the warning color under 24 hours; the exact UTC expiry remains in the `<time>` title and label, and server rendering uses the fixed UTC value until mount. Clicking a row or its price copies the exact price through `useUiClipboard` and briefly shows "Copied". Buy orders at or below half the best buy are dimmed as lowball, with a tooltip and screen-reader text; hovering or focusing restores them. Reaching either scroll edge loads the adjacent 100-row keyset page, keeping at most 100 rows mounted; the list ends with a loading row or "End of order book". Prices describe individual orders, not quantity-aware quotes.

## Price history

Price History is keyed by profile revision and type, with its own source time (`validatedAt`). For region profiles, opening the tab records a history demand. While the demand is accepted but history is still uncollected, the tab shows the scanner loader ("Collecting daily price history") and rechecks every four seconds for up to 90 seconds, then offers Check again. A demand rejected by the per-profile limit (256 distinct types) and other request failures have their own messages. Watched-types profiles never send a demand.

**Daily Average** is the source average, not a median; high/low is the source range and volume is the daily source volume. Display-only five- and twenty-day moving averages use exact cent values and need that many consecutive valid days; the twenty-day Donchian band uses the highest high and lowest low over the same days. Gaps break a window and nothing is interpolated. The lazy Canvas chart plots two or more valid days with a separately scaled volume band and a full-history overview whose handles expand or slide the visible range; pointer or modifier-wheel gestures adjust price zoom and pan. Reka tooltips show exact source values on hover and keyboard inspection, and the focused canvas exposes the selected day in its accessible label. It redraws on data, selection, range, size or theme changes rather than animating continuously. One valid day is shown as text; no valid days show a no-history state.

The production Nuxt build emits `fuse.js/worker-script?url` as a same-origin worker asset. Headless Chromium created workers from it. A temporary shard benchmark (removed after proof) ran 25 queries for 20,000 synthetic names. Desktop one/two/four-shard startup measured 85/56/50 ms, search p95 34/18/12 ms, and approximate browser RSS deltas 56/68/80 MB. At 390×844 with 4× CPU throttle, startup measured 197/175/144 ms, p95 34/21/14 ms, and RSS deltas 52/53/61 MB. The page uses two shards below 30,000 types and four at the 32,000-type ceiling.

## Historical production browser measurements

These measurements belong to the earlier autocomplete layout, before the Reka Tree, four-character search threshold, and observed-end paging changes. They are retained as historical evidence, not performance results for the current layout. The isolated fixture used official build 3542233 and a 32,000-type growth case. Fast 4G emulation was 4 Mbps down, 2 Mbps up, 150 ms latency; mobile was 390×844, DPR 2, with 4× CPU throttle. Warm p95 used 25 distinct exact-name queries, with no search-induced task over 50 ms. Hydration is approximated by navigation response end to the mounted mark.

| --------------------------- | ---------: | ------------------------: | -----------------------: | -----------: | ----------: | --------------: | --------: |
| Official / desktop          |     205 KB |                    819 ms |                    63 ms |         5 ms |       52 ms |          120 ms |       289 |
| Official / mobile emulation |     205 KB |                    854 ms |                    72 ms |        21 ms |      128 ms |          214 ms |       276 |
| 32,000 / desktop            |     269 KB |                    829 ms |                    72 ms |         8 ms |       67 ms |          132 ms |       289 |
| 32,000 / mobile emulation   |     269 KB |                  1,402 ms |                    81 ms |        26 ms |      171 ms |          263 ms |       276 |

That SSR HTML transfer was about 238 KB uncompressed; the independent tree representation was about 25 KB gzip and the largest first direct-type page about 1.1 KB gzip. The emulated CPU throttle does not establish physical mid-tier mobile or field-network behavior. Current-layout production performance remains to be measured.

Usage example: type `Rif`; the tree stays visible and no index request occurs. Type `Rift`; the input remains editable during index loading, then current-revision results replace the tree. Scroll to the last item in a large group; one more 100-item page loads and appends without a button. A late result from an older query or SDE revision cannot replace the current one.
