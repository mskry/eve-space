# Trading inventory contract

Trading supplies personal and corporation inventory reads through the mounted `/graphql` endpoint. It is installed as an optional module, disabled by default. Personal reads do not depend on Member Audit; the optional corporation provider belongs to Member Audit. The private `/trading` page uses the platform's memory-only aggregate admission lifecycle; see [the interaction contract](experience.md). HR/director roles and exact reviewer permissions apply across all current managed corporations, including an alliance's member corporations; each request selects one corporation. Corporation release retains the independent EVE-16 deployment gates.

## Personal sources

Core admits all current attached characters by default, or an explicit narrowing selection. Only evidence-readable subjects reach the character source reader. Missing authorization and pending recovery remain visible coverage gaps without source reads. Personal sources do not depend on organization membership or Member Audit. See [the core admission policy](../../../docs/trading-inventory-admission.md).

The reader uses the existing registered character asset-page representation. Each page crosses the caller's shared work admission and cancellation signal. The host must keep live authority checks before use, after queued admission, before reuse and before release; the reader also refuses a token generation that differs from its admitted subject. It does not fetch the full-inventory HTTP route, reduce a partial source-page connection, or request custom asset names. Existing single-character APIs retain their own bounds and behavior.

Supported aggregate bounds are 20 personal subjects, 20 source pages across the selected scope, 1,000 records per source page and 10,000 records per character. These are implementation limits; target deployment capacity evidence is recorded separately during Group 7. After reading a source's first page, the reader reserves its entire advertised window before admitting further source work. Exceeding a known source bound fails the whole read with narrowing guidance. It never chooses the first subjects or publishes quantities from whichever pages finished.

A source contributes only after all advertised pages succeed with matching page counts and authorization generation. Failed or inconsistent pages exclude all quantities for that character; independent complete sources can still contribute with the gap visible. Cancellation, shared operation budget exhaustion and authority changes refuse the field rather than becoming ordinary availability gaps. A complete empty observation has a source identity and included coverage, while an unavailable observation has no source identity and no asserted quantity.

## Quantities and locations

Repeated identical physical item IDs within one observation count once. Inconsistent copies invalidate that source. An item ID observed under multiple selected characters is excluded from every asserted total, and each affected character receives `conflicting-source` coverage. Unaffected items still contribute. Independent observations cannot establish which owner is current.

Quantities must be positive safe integers at normalization. Zero, fractional, negative, nonfinite or unsafe representations invalidate the source; no legacy singleton quantity encoding is guessed. Sums use integer arithmetic and serialize as decimal strings, preserving totals above JavaScript's safe integer range.

Container chains resolve to the physical root within each complete observation. Containers contribute their own item quantity; their contents contribute separately. Missing parents and cycles use the `unresolved` bucket. Other roots remain distinct `restricted` buckets with no private-structure lookup. Known station/system roots whose public enrichment is unavailable use `unknown` status without losing valid quantities.

Type and physical-root enrichment is batched across the complete selected observations. Only public station/system names and static location details are resolved. Missing static type data retains a deterministic unknown label and null group/category metadata. Blueprint copies retain the source copy flag; known blueprint-category types without that flag group as originals. Ordinary types remain separate from copies. No packaged volume is presented as actual cargo volume.

Groups use type, blueprint distinction and physical-root identity. Current and readable stale quantities occupy separate decimal fields. Holder contributions retain their character, owner and source timing and are separate rows rather than embedded unbounded lists in every group. Type, group, category and location filters apply after complete source reduction; they do not shrink expected coverage or convert an excluded source into an empty observation.

## Source clocks and coverage

Each complete source has an observation digest of every ordered page fingerprint. It binds the records, page counts and page validation/expiry clocks. The personal `observedAt` and `validatedAt` are the earliest page validation time; ESI asset pages supply no separate authoritative observation timestamp. Page and character observations can occur at different times and are not a simultaneous snapshot.

`freshUntil` is the earliest page freshness deadline. `retainedUntil` is the earliest source-owned readable deadline supplied by the gateway, bounded by its actual cache retention and stale policy. This deadline is read metadata, not authorization or a new retention policy. Legacy results without that metadata conservatively expire at their freshness deadline.

Current quantities require every page to remain fresh. Stale quantities require the gateway's permitted outage fallback (`esi-unavailable` or `esi-cooldown`) and an unexpired readable deadline; ordinary expiry or response-invalid fallback cannot contribute. Evidence already outside that deadline yields `beyond-retention` coverage. A contributing source expiring during subsequent work requires restart. Freshness never extends itself because enrichment or presentation succeeded.

The reduction reports traversal completeness separately from source completeness, expected visible subjects, per-character source correlation and coverage counts. Included-current, included-stale, authorization-required, unavailable, incomplete, beyond-retention and conflicting-source are supported personal states; never-collected remains available for stored corporation sources. Coverage gaps disclose only admitted visible characters and never assert undisclosed-alt coverage. Missing observations have unknown holdings, not zero holdings. Totals describe observed possessions and grant no stock commitment or authority to move another character's items.

The internal reduction retains finite source-bounded rows for host pagination. Public connections contain at most 100 rows. No cross-request private aggregate cache or browser persistence is introduced.

## GraphQL fields and pages

The nullable `Query.trading` root discovers the enabled module for an authenticated session and grants no inventory source authority. Its separate nullable fields are:

| Field                  | Subject selector                  | Authority                                                                                                                        |
| ---------------------- | --------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| `personalInventory`    | Optional `characterIds: [EveId!]` | Live ownership and assets authorization across the selected attached characters                                                  |
| `corporationInventory` | Required `corporationId: EveId!`  | Current application HR/director reviewer admission with both `trading.inventory.corporation.read` and `member-audit.assets.read` |

Both accept `kind: TradingInventoryKind = groups`, `first: Int = 50`, and optional `after: String`. `groups` additionally accepts `filters: TradingInventoryFilters` with `typeId`, `groupId`, `categoryId` and `locationKey`. `holders` requires the exact returned `groupKey`; `coverage` accepts neither filters nor a group key. Filters cannot narrow coverage. An omitted or null personal selection defaults to all attached characters; `[]` selects none. IDs and exact quantities serialize as strings.

`TradingInventoryView` carries contract version 1, scope, optional corporation ID, the full view fingerprint, traversal/source completeness, expected subject count and named coverage counts. `groups`, `holders` and `coverage` are separate connections with `rows`, `endCursor` and `hasNextPage`. Only the requested kind has rows. Groups carry type/group/category, blueprint and physical location, plus exact current and stale quantities. Holders carry permitted character/owner identity, contributions and source clocks. Coverage carries visible character identity, a safe state and nullable source clocks. Counts describe the entire visible subject set even when a page contains one row or a row filter excludes every group.

Group order is type ID, blueprint and physical-root key. Holder and coverage order is character ID. Personal pagination reduces all complete sources before slicing. Corporation reads use bounded source-owned set queries, and the host merges coverage-only subjects without sending them to the evidence provider. A holder request preserves its original subject scope and records only the returned permitted holder attribution. Required audit persistence failure refuses the corporation field.

## Cursor and work policy

Cursors are bounded opaque base64url checkpoints, at most 4,096 characters, containing SHA-256 authority/query/view digests and one bounded keyset position. Corporation checkpoints wrap the source provider's bounded checkpoint. They contain no subject vector, quantity, token or session value and grant no authorization. The authority digest includes the live actor, selected scope and complete authority tuple set; the view digest includes complete source identities and clocks. The query digest uses normalized filters or holder group identity. Page size may change between reads. Cursor syntax, query and authority are checked before asset or provider evidence reads, and the reconstructed source view must match before release.

Restart pagination after a source observation or authority revision changes, or a contributing source expires. Personal source freshness/retention is also rechecked before request-local reuse. Corporation providers compare their complete observation vector after asynchronous storage work. Known invalidation refuses the whole affected field rather than releasing a reduced or mixed view. Independent personal/corporation aliases can succeed or fail separately; exhaustion of the shared operation work budget cancels the whole response.

The installed personal declaration reserves a source cost of 20 and the corporation declaration 250 even for `first: 1`. Each output connection declares its 100-row maximum. Each personal page, enrichment operation and corporation persistence call crosses the existing shared request admission with a queued live-authority check. Authority checks use slot-local work, so an occupied backend slot cannot wait for another slot for its own recheck. Request-wide limits remain 32 backend invocations, concurrency four, a 15-second deadline, 2 MiB memo/response bounds, 5,000 selected cost, 1,000 selected rows, 30 aliases and 12 read bindings. Personal source reductions may be reused only within the same admitted request. No global budget has been increased.

## Safe errors and generated operations

| Code                                                                                                                                    | Meaning                                                                                                                                                                                       |
| --------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `AUTH_REQUIRED`, `RESOURCE_UNAVAILABLE`, `MODULE_DISABLED`                                                                              | Reauthenticate or verify module availability. The host returns generic `RESOURCE_UNAVAILABLE` for disabled fields; the browser can report `MODULE_DISABLED` from its current runtime metadata |
| `INVENTORY_SCOPE_DENIED`                                                                                                                | The selected scope is unavailable, including indistinguishable unknown/non-owned personal IDs or an absent corporation provider                                                               |
| `ORGANIZATION_PERMISSION_REQUIRED`, `ORGANIZATION_REVIEWER_REQUIRED`, `ORGANIZATION_MEMBER_BLOCKED`, `ORGANIZATION_COMPLIANCE_REQUIRED` | Current corporation reviewer admission was refused                                                                                                                                            |
| `INVENTORY_AUTHORIZATION_CHANGED`, `INVENTORY_SOURCE_CHANGED`, `INVENTORY_RESTART_REQUIRED`                                             | Discard the cursor and restart with live admission                                                                                                                                            |
| `INVENTORY_LIMIT`                                                                                                                       | Narrow the selected scope; no silently truncated aggregate is returned                                                                                                                        |
| `BAD_USER_INPUT`                                                                                                                        | Invalid selectors, filters, group identity or page size                                                                                                                                       |
| `OPERATION_LIMIT`, `OPERATION_CANCELED`                                                                                                 | Shared work/output budget exhausted, canceled or timed out                                                                                                                                    |

Unclassified failures retain the host's redacted `INTERNAL_SERVER_ERROR`. Every protected response is non-storeable, including mixed allowed/denied aliases. Missing source authorization appears only as safe coverage for visible subjects and grants no evidence method.

The offline schema is generated with the installed contribution. `trading-operations.graphql` supplies `TradingPersonalInventory`, `TradingCorporationInventory`, personal/corporation holder operations and personal/corporation coverage operations. `trading-graphql.ts` derives typed documents, selected results and variables from that schema. `pnpm graphql:check` checks generation drift and isolated Trading operation types; `pnpm registry:check` verifies package artifacts and exact installed bindings.

## Measured capacity

Group 7 verified a mounted personal read over 20 complete 1,000-item source pages (20,000 items) and a real PostgreSQL provider read over 250 corporation subjects with 100 projected items each (25,000 items). The personal fixture took 57.18 ms with 20 page calls; the corporation fixture took 70.45 ms with three set persistence calls. The latter verifies 100-holder continuation, 251-subject refusal and a two-second database statement timeout. These are representative synthetic measurements rather than deployment latency guarantees. The personal page boundary is mocked; the corporation routines execute on PostgreSQL 17.

See [Trading operations](../../../docs/trading-inventory-operations.md) for memory/output measurements, the complete SQL plan, shared deadline limits and deployment/rollback evidence. The declared limits remain unchanged. Corporation rollout is separately blocked until EVE-16 assets disclosure, enablement, real collection, capacity and privacy gates have accepted target evidence.
