## Findings

No unresolved failure in the revised section 7 scope. Standard discovery needed an introspection-only depth ceiling of 16; ordinary application depth remains 10 and the existing expansion/output/work limits remain enforced. A limit-plus-one discovery test rejects excess depth.

The application-client lifecycle review identified two gaps, now fixed: owned GraphQL keys bypassed character-scoped cleanup, and HTTP 200 authentication field errors bypassed authorization-denial hooks. Asset keys now extend the recognized numeric character prefix while retaining owner/revision isolation; selector keys use the character collection scope. Query contexts supply the application query cache, and field errors notify `reportPrivateQueryAuthorizationDenial()` while preserving the partial envelope. Authentication denials take precedence over character denials. Canceled or no-longer-admitted requests cannot report obsolete denials. Transient source, cursor-restart and input errors leave private data intact. Regression coverage verifies character removal/revision/scoped cleanup, unaffected characters and public data, and durable character/organization partition deletion with cross-tab notification after `AUTH_REQUIRED`.

## Policy conflicts and missing evidence

- The original OpenSpec requested a custom private resource explorer. The user explicitly replaced it with standard GraphiQL. The design, task list and explorer requirement now reflect that direction. GraphiQL is a standalone inspection tool: completed output remains in its page memory until navigation/reload, and subsequent reads use live server authorization. It does not integrate with the application's retained-resource presentation lifecycle. Existing authenticated resource views and query-persistence lifecycle are unchanged.
- The checklist's Hono-only contract language and comprehensive GraphQL per-field inventory are section 8 work. This report does not claim an audit of every installed field or organization/private resource path.
