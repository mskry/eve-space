# Aggregate inventory admission

Core owns the fixed subject set; the personal asset reader and Member Audit retain source ownership. Trading receives intentional inventory results through declared read capabilities. Groups 2–6 establish core admission, pure inventory semantics, complete personal source reads, Member Audit projections, GraphQL composition and private presentation in `add-authorized-aggregate-inventory`. See the [Trading source contract](../features/trading/docs/contract.md) for quantities, clocks and coverage.

Reviewer trust, roles and permissions apply organization-wide across all current managed corporations. In an alliance deployment, an admitted HR/director reviewer with both exact permissions may select any current member corporation, regardless of the reviewer's own corporation. Each read still binds exactly one selected corporation and excludes characters outside it. No corporation-specific grant is required. Unmanaged or departed corporations and alliance-wide wildcard reads remain refused. This policy was confirmed on 2026-10-03 and reconciled in task 2.2's change artifacts.

## Binding and release

`auth/inventory-subject-store.ts` performs bounded ownership/token/lifecycle batch reads without organization dependencies. `organization/inventory-subject-store.ts` derives corporation subjects under a repeatable-read organization snapshot. The platform source adapter batches the existing authoritative resource classifier over this exact set; core never queries Member Audit tables.

Bindings freeze canonical selections, subjects and readable subsets. Fingerprints cover the actor, scope, owner/lifecycle/revision state, affiliation period, effective reviewer context, policy version, disclosure revision and section activation. Coverage-only subjects stay in the core binding and are excluded from nominal provider evidence admissions. Missing source scope or disclosure does not become evidence authority. Complete observation identities and freshness remain the source owner's responsibility; admission itself does not assert collected inventory or complete-empty observations.

`createInventoryReadGuard` checks live session and the original complete binding before use, after a queued backend slot is acquired, before request-local reuse, and before release. A changed binding rejects the entire field with a restart outcome; it does not substitute a smaller set into an existing read. Default selection also detects newly attached/current members. Slot-local checks use the supplied local work runner; orchestration must remain outside a backend slot when it needs multiple source operations. Personal readers must use the guarded runner for each backend operation, and corporation providers must use it for their batch operation. GraphQL memo reuse must call `assertCurrent`, and every successful response, including a reused result, must pass `release`.

## Access auditing and disclosure

Core migration `021_inventory_access_audit.sql` adds a separate append-only organization access record, retained independently of domain-event recovery and source snapshots. It changes no existing migration or source table. API startup applies it; worker readiness automatically requires the current core migration inventory. Roll back exposure through module disablement or a compatible forward repair; preserve retained audit data.

Corporation aggregate release requires one persisted decision with at most 250 safe target authority tuples. Holder release requires an explicit selection of at most 100 readable admitted characters. Records contain actor, permitted corporation, organization/policy versions, section/disclosure/activation, lifecycle/generation attribution and whether evidence was admitted. They contain no character names, observations, contents, quantities, filters, query text, cursor data, credentials or arbitrary module metadata. Unknown/refused scopes record no corporation or target identities. In-flight authority denials retain their original organization/policy attribution; fresh admission denials use the current deployment context. Failed audit persistence refuses release. Personal reads do not create organization evidence access records.

The initial aggregate view stays within the existing assets disclosure: types, quantities and locations for authorized organization policy/readiness review. It asserts observed holdings only, with no stock commitment, movement authorization, exports or planning actions. No disclosure wording/revision or consent store changes here. Any later material purpose expansion must use the existing assets disclosure revision and exact-character acceptance flow. Corporation deployment acceptance remains independently gated by EVE-16.
