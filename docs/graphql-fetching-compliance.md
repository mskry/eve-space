### Presentation and clocks

GraphiQL presents server-validated arbitrary results and field errors without a second viewer authorization system. Storage and URL editing are disabled. Reload/navigation discards editor/output memory. A cookie change alone does not erase an already displayed result; the next request is admitted again, and reload clears the display. This is the generic tool contract, not application retained-data admission.

Application options are disabled by default and require a caller-owned `canRun` gate before and after asynchronous execution. Private identities capture owner, exact character and admission revision. Application consumers must apply the same current-context gate to presentation; these options currently have no mounted resource-view consumer. Authorization field errors are forwarded to `app/query-persistence/runtime.ts`, including HTTP 200 denials. Obsolete/canceled responses cannot report a denial into a newer context. Queries have zero residency/freshness/retry and explicitly exclude persistence; no new browser snapshot category is admitted.

| Upstream freshness            | Assets retain per-page gateway `validatedAt`/`cachedUntil`, outage-stale provenance; Market observation/history/reference have independent clocks. Catalogue/profile GET verdict caps are 30s, book/orders 10s constrained by source expiry, history 60s constrained by expiry; references are no-store. |
| Browser freshness / residency | Curated options use `staleTime: 0`, `gcTime: 0`, `retry: 0`, `enabled: false`. Viewer performs explicit execution without automatic retries.                                                                                                                                                             |

| Authorization validity        | Live session; immutable subject lifecycle/revision/scope; applicable module/organization guard; checks before reuse and release. Cursors or cached values never grant authorization.                                                                                                                     |
| HTTP response caching         | POST/private/mixed/introspection/error/stale/incomplete/missing-verdict operations use no-store.
