## Findings

No fetching-policy change is required for EVE-70. `assertCurrent()` checks host/module eligibility; Market SQL independently checks profile enablement and revision. An accepted batch commits atomically, while only complete publication changes the current pointer. Private structure collection remains separate.

### ESI-04: Owner publication after lease release

When an ESI request owner published its response and released the lease before a follower's TTL query, the follower previously skipped the shared-envelope read and issued a duplicate upstream request. The existing CI fixture left that unexpected second request unresolved. The repair reads the published envelope before reacquiring a lease even when TTL is zero. A regression controls this ordering through the actual Redis adapter and registered mail representation; it asserts that the owner returns upstream data, the follower returns the same cached data, and only one upstream request occurs. Existing lifecycle/generation and committed-fence checks still protect that envelope.
